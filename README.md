# 神託の勇者

手動コマンドと日本語プログラムで戦う、静的ブラウザゲームの基本システムです。フレームワーク・外部API・ビルド処理は使いません。

## 起動

リポジトリのルートで次を実行してください。

```sh
python3 -m http.server 8000
```

PCでは `http://localhost:8000` を開きます。GitHub Codespacesでは「ポート」タブから8000番をブラウザで開けます。スマートフォンも転送先URLから遊べます。ES Modulesを使うため、HTMLの直接ファイル起動ではなくHTTP経由で開いてください。

GitHub Pagesにリポジトリのルートを公開しても動作します。バックエンドサーバーは不要です。保存領域はブラウザ・公開URLごとに別になります。

## 遊び方

初期状態は全構文が使える開発用テストモードです。敵の行動パターンを確認して、手動で攻撃・防御・回避・覚えるを選択するか、コードを書いてRUNします。見張りゴブリンに対する初期コードは勝利まで動きます。

PC・横幅のある画面では、左に敵と手動コマンド、右にエディタを表示します。スマートフォンでは縦に並びます。戦闘設定と保存管理は折りたたんであり、必要な時だけ開けます。ヘッダーの「リファレンス」は `reference.html` を別タブで開き、戦闘中のコードを保持したまま文法や基本ルールを参照できます。

攻撃・特技は防御、魔法は回避で対応します。攻撃は1ダメージ、被弾は即死です。死亡後は編集してRETRYできます。コードが終了した場合はその戦闘状態のまま手動へ戻ります。RUN中に中断や編集はできません。

テキストとコマンド入力は同じエディタを使用します。構文補助はカーソルの行の先頭へ閉じる行を含むテンプレートを挿入します。既存コードの意味・カウンタ名の衝突まで自動修正する機能はありません。最終的な構文検証はRUN前に行います。

セーブは選択中のプログラムを更新し、新規保存は別のプログラムを作ります。名前変更には名前欄を使用します。下書きと累積RETRY数もlocalStorageに保持します。保存できない環境では理由を表示します。テキスト出力はエディタの内容を `.txt` でダウンロードします。

詳細ログは死亡・勝利後だけ閲覧できます。直近1戦のログを保持し、RETRYや敵切替で消去します。ログには実行時の命令も残ります。行番号ボタンは現在のエディタの対応行を選択するため、編集で行を増減した場合は実行時の命令表示も参照してください。

## 文法

```text
攻撃する
防御する
回避する
覚える

5回繰り返す
    攻撃する
ここまで

iを1から10まで繰り返す
    もし、i % 2 = 0ならば
        防御する
    違えばもし、記憶 = 「詠唱」ならば
        回避する
    違えば
        攻撃する
    ここまで
ここまで
```

1行1命令。インデントは任意です。空行と `#` / `//` から始まる行は無視します。条件は「ならば」、分岐・繰り返しは「ここまで」で閉じます。比較は `= == != < > <= >=`、算術は `+ - * / %`、論理は大文字の `AND OR NOT`。括弧を使えます。文字列は `「…」`、`"…"`、`'…'`（エスケープ構文はなし）。整数・小数・単項符号を使えます。演算子の優先順位は乗除剰余→加減→比較→NOT→AND→OR。同順位は左結合です。比較の連鎖は避け、ANDでつないでください。

参照できる値は `ターン`、`敵HP`、`記憶`、有効な範囲のループカウンタです。敵の現在行動や任意変数は参照できません。カウンタは昇順で両端を含み、開始値が終了値を超えると0回です。同名カウンタの入れ子は禁止です。回数は0以上の安全な整数で、開始・終了値はループに入る時に評価します。条件は判定時の戦闘状態を参照します。AND/ORは短絡評価し、数値・文字列の真偽判定は0・空文字が偽、それ以外が真です。等値比較は型も一致する必要があり、算術は数値専用です。

最大1000行・200000文字・式512トークン・入れ子64段・実行命令数50000。構文は実行前に全体を検証します。0除算や動的な回数の不正などは実行時エラーで、その時点の戦闘状態を保持して手動に戻ります。低速は行動間550ms、高速は8ms。行動のないループも100処理ごとにブラウザへ制御を返します。eval/new Functionは使用しません。

## ファイル構成

- `index.html` / `styles.css`：日本語UI、レスポンシブ配置。
- `reference.html`：別タブで開く文法・戦闘ルール。
- `js/data.js`：テスト敵・15章の構文解放データ。
- `js/enemy-graphics.js`：敵別のPNG参照と未設定時の仮SVG。
- `js/battle.js`：戦闘状態、手動・RUN共通のターン処理。
- `js/language.js`：字句解析、構文解析、式評価、ジェネレータ実行。
- `js/runner.js`：RUNのロック、実行速度、制御の返却。
- `js/storage.js`：localStorageによるプログラム管理。
- `js/app.js`：画面と各機能の接続。
- `tests/core.test.js`：戦闘・言語・RUN・保存の自動テスト。

## テスト

### 敵の画像を差し替える

生成した透過PNGを、次のファイル名で配置してください。対応する敵の画像が自動的に切り替わります。

```text
assets/
└── enemies/
    ├── README.md    # 配置手順
    ├── goblin.png   # 見張りゴブリン（後から追加）
    ├── mage.png     # 月影の魔導士（後から追加）
    ├── guardian.png # 古城の番人（後から追加）
    └── slime.png    # 訓練スライム（後から追加）
```

PNGの実画像はまだ未配置です。画像がない敵は仮SVGを表示します。透明な背景、正方形、256×256pxを推奨します。表示時は縦横比を保って現在の小さな枠に収めます。

参照先は `js/enemy-graphics.js` にあり、パスはそのJSファイルからの相対パスです。モジュールURLを基準に解決するため、GitHub Pagesのサブディレクトリでも使えます。画像追加・差し替え後はブラウザを再読み込みし、古い画像が残る場合はキャッシュを無視した再読み込みをしてください。

ChatGPTアプリ用の画像生成プロンプトは `docs/enemy-image-prompt.txt` にあります。透過PNGをダウンロードする依頼に更新してあります。

### 自動テスト

Node.js 24以降で、依存パッケージのインストールなしで実行できます。

```sh
npm test
```

ブラウザでは手動戦闘、死亡後の編集・RETRY、RUN中の操作ロック、低速行ハイライト、保存管理、テキスト取込・出力、章の構文制限、スマートフォンのレイアウトを確認してください。
